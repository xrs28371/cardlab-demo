# 卡片工场 CardLab — 第 1 阶段演示（骨架 + 工具①）

统一 MVP 方案的第 1 阶段产出：统一前端骨架 + 卡片渲染模板 + JSON 配置结构，
以及第一个工具「X 价值计算器」的完整闭环（输入 → 假分析 → 9:16 卡片 → 保存图片）。

## 架构

纯静态站点（可直接部署 Cloudflare Pages），无构建步骤。前端分六层，
每层只管一件事，层与层之间只通过配置与数据对象通信：

| 层 | 职责 |
|---|---|
| Config 配置层 | 站点信息与工具矩阵来自 `config/tools.json`；每个工具的玩法配置路径写在该工具自己的 `pack` 字段里，启动时按表动态加载、按工具 id 登记；拉取失败自动回退内置默认配置，页面永远能跑 |
| Router 路由层 | 三个视图切换 + hash 深链（`#x-value` 直达工具页） |
| Views 视图层 | 首页矩阵全部由配置渲染；工具页是单输入型工具的通用壳（其他交互类型的新工具加自己的视图模块接入路由即可） |
| Engines 引擎层 | 每个工具一个纯函数引擎（输入 → 结果数据对象，不碰 DOM），按工具 id 注册 |
| Card 卡片层 | 卡片模板按工具 id 注册；结果数据对象 → 9:16 卡片（数字滚动、字号自适应、二维码与水印），卡面文案来自该工具的 pack 配置 |
| Export 导出层 | 离屏克隆渲染 1080×1920 PNG（克隆内重绘二维码、同步终值字号）；桌面自动下载，移动端出浮层长按保存 |

**新增一个工具的标准动作**（路由与导出主干不改）：
1. `config/tools.json` 加一条工具配置（名称、描述、批次、状态、pack 路径、模板 id）；
2. 加一份该工具的玩法配置 JSON；
3. 在 Engines 里注册一个同 id 的纯函数引擎；
4. 在 CardTemplates 里注册一张同 id 的卡片模板。

## 本次演示范围

- 首页工具矩阵：六个工具全部在列，仅工具①可点开（其余按批次标注）。
- 工具① X 价值计算器：用户名 → 1.5 秒假分析（步骤文案+进度条）→ 估值卡片。
  估值公式纯属虚构（哈希种子保证同名恒定），三档分布经对数分布+幂次整形
  调到大致各占三分之一；文案池、档位线、币种、奶茶单价全在
  `config/valuation.json`，改数值改文案不用动代码。
- 卡片页按验收标准只保留「保存图片」一个主按钮（外加一个弱化的「再测一个」）。
- 产品名、域名为占位（卡片工场 CARDLAB），上线时在配置里替换。

## 目录

```
index.html            三个视图的骨架
assets/style.css      全站样式（卡片 540×960，导出 scale=2 → 1080×1920）
assets/app.js         六层骨架实现
assets/vendor/        html2canvas、qrcode（本地托管，不依赖 CDN）
config/tools.json     站点信息 + 工具矩阵
config/valuation.json 工具①玩法配置
```
